## Что делает парсер

Автоматически обрабатывает лиды из колонки **«База»** в Brizo CRM:
квалифицирует компании по финансовым показателям, заполняет карточки данными
из Checko.ru и перемещает подходящие лиды в **«Парсю»**.

## Шаги обработки каждого лида (строго по порядку)

### a. Назначить ответственного
`assign_to_me(page, lead_id)` — назначает Нику Серафимову ответственной за сделку.

### b. Получить детали сделки
`get_lead_details(page, lead_id)` — читает поля карточки через API:
- `inn` — ИНН компании (без него → пропускаем с ошибкой)
- `website_field` — поле «Сайт»
- `checko_url_field` — уже заполненная ссылка на Checko

### c. Проверить поле «Сайт» и «Корпоративная почта»
Отклоняем «Нет КД» только если **оба поля пустые** — и «Сайт», и «Корпоративная почта».
Если заполнено хотя бы одно → продолжаем анализ.
Причина отказа: `"Нет КД"`.

### d. Получить данные из Checko
- Если `checko_url_field` уже заполнен → `get_company_data_from_url(url, inn)`
- Иначе → `get_company_data(inn)` (поиск по ИНН)
- Если Checko не ответил (ошибка / таймаут) → **пропускаем без комментария** (сделка остаётся чистой, следующий прогон повторит попытку)

### e. Заполнить поле Checko в карточке
Если поле ещё не было заполнено и `checko_url` найден → `fill_checko_field(page, lead_id, url)`.

### f. Финансовая квалификация
`qualify_company(company)` — проверяет (в `qualifier.py`):

| Условие | Причина отказа |
|---|---|
| Выручка > 1 млрд руб | `"Интересные, но ярд"` |
| Налог на прибыль (последний год) < 5 млн руб | `"Маленькая выручка/мало налогов"` |
| Нет данных по налогу | `"Маленькая выручка/мало налогов"` |

Используется `amounts[0]` (последний/самый свежий год), **не** `max(amounts)`.

Если не прошли → `reject_lead(...)` → **стоп, больше ничего не делаем**.
Комментарий о часовом поясе НЕ оставляем для отклонённых лидов.

### g. Добавить комментарий с часовым поясом (только для прошедших)
`get_timezone_comment(legal_address)` → `add_comment(page, lead_id, tz)`.

Таблица часовых поясов (UTC относительно МСК, МСК = UTC+3):

| Регион | Метка |
|---|---|
| Калининград | `-1ч` |
| Самара, Удмуртия, Ульяновск, Саратов | `+1ч` |
| Екатеринбург, Свердловск, Тюмень, Курган, Челябинск, Оренбург, Пермь, Башкортостан, ХМАО, ЯНАО | `+2ч` |
| Омск | `+3ч` |
| Новосибирск, Красноярск, Кемерово, Томск, Алтай, Хакасия, Тыва | `+4ч` |
| Иркутск, Бурятия, Забайкалье | `+5ч` |
| Якутск, Амурская обл | `+6ч` |
| Владивосток, Приморье, Хабаровск, Еврейская АО | `+7ч` |
| Магадан, Сахалин | `+8ч` |
| Камчатка (паттерны: `камчатк`, `камчатск`), Чукотка | `+9ч` |
| Всё остальное (Москва, МО, СПб, ЦФО и т.д.) | `мск` |

### h. Переместить в «Парсю»
`move_to_stage(page, lead_id, STAGE_PARSING)`

### i. Добавить ЛПРов из Checko
`get_lpr_contacts(company)` → `add_lpr_contacts(page, lead_id, lpr_contacts)`

Правила отображения должности:
- Роль пишется только в поле **Имя** (в сокращённом виде), поле Должность **не заполняется**.
  Причина: Должность — автокомплит Brizo, принимает только значения из своего списка;
  свободный текст приводит к отмене формы при сохранении.
- Генеральный директор → суффикс `"гендир"` → имя: `"Иванов Иван Иванович гендир"`
- Учредитель → суффикс `"учред X%"` (всегда указывать долю) → имя: `"Петров Пётр Петрович учред 45%"`
- Если одно лицо и директор и учредитель → роль `"гендир"` (директор важнее)
- Перед созданием контакта: `_open_deal(page, lead_id, force=True)` (переоткрыть карточку)

## Источник данных по налогу на прибыль

Парсер читает **«Налог на прибыль»** из `/taxes/data` (ФНС, официальные данные) — последние три года, самый свежий год первым.
Правило: хотя бы раз за 3 года налог на прибыль ≥ 5 млн руб.

Запрос к `/taxes/data`:
1. Сначала **curl UA** (`_CURL_SESSION`) — обходит rate-limit, не таймаутит
2. Если не сработало — **SESSION** (browser UA + прокси)
3. Если оба провалились — `income_tax_amounts = []` → компания **не квалифицируется**
   (НЕ используем данные главной страницы: они агрегированные и могут показывать не тот налог)

## Известные особенности и баги (исправленные)

- **Камчатка**: паттерн `"камчатк"` не матчил `"камчатский"` — добавлен `"камчатск"` (исправлено)
- **Поле Должность**: заполняется через JS-клик, не через Tab+type (race condition)
- **Открытие карточки после смены этапа**: нужен `force=True` в `_open_deal` перед добавлением ЛПРов
- **ОРЕХОВО-ЗУЕВСКАЯ ЭЛЕКТРОСЕТЬ**: выручка 9.2 млн, налог 17.2 млн — аномалия данных, корректно проходит (проверяем только налог)
- **taxes/data таймаут**: ранее при неудаче `/taxes/data` использовались ненадёжные данные главной страницы → компании могли пройти с неверными цифрами. Исправлено: теперь curl UA + при неудаче данные сбрасываются.
